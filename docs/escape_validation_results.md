四个历史死胡同卡住快照，使用实际 ROS planner、控制器、模拟相机深度、碰撞检查和 RecoveryExecutor。先原地扫描 360°，重新筛选全程 footprint 已观测通畅的退让动作，再执行现有 1.8 米退让序列，最后恢复原 planner。任务目标始终为 [4, 0, 0]。

结果：4/4 到达，最终距任务目标均小于 0.35 米。四个快照来自同一个场景，不能视为跨环境成功率。选边由验证脚本指定；这些运行没有调用模型，不能归功于模型判断。

新增 `observed_retreat_selection.py`：逐采样点审计完整 footprint，单个 unknown/blocked cell 即排除；每侧保留最长已观测通畅退让，最多两个。辅助模式的等证据选择有明确规则：优先少尝试过的策略，再按固定 ID；模型偏好字段保持空。未替换现有模型 selector，未启用普通 web 服务。

新增隔离 live harness，要求实时规划报告 <0.5 秒；完整扫描、平移误差 <=2 cm；保留原执行器碰撞与新鲜度保护。域锁防止 harness 并发使用相同域。

3 个新增单元测试通过，8 个观测/旧筛选回归检查通过。容器没有 pytest，因此旧纯函数测试通过直接调用验证，未声称 pytest 成功。

探索性临时目标分支发生 1 次碰撞，已丢弃其实现。与该分支重叠的快照 2 运行排除，随后完全独占 ROS 域重测成功。仅上述四个有效运行计入统计。

结论：这个死胡同场景不需要修改 planner 或增加临时目标；扫描后选择足够长的已观测退让即可恢复原导航。剩余产品接入工作是将该规则辅助路径作为显式实验模式接到 Web 控制面，并与模型独立判断分别统计。模型本身的选项顺序敏感及同分拒绝仍未修复。
