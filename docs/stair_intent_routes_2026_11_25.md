# 楼梯转向意图、下楼目标路径及斜视踏面（2026-11-25）

本次针对 2026-11-25 两段实测记录中的原地转向前移、下楼目标跳到高处/墙后、上楼部分可见踏面被当墙的问题。基线为 `ad4f3c0`。两段记录均有大量人工介入；固定传感器与原 Path 回放用于检查软件约束，不能作为修改后真机自主通过的成绩。具体机器结果见 [验证 JSON](validation/stair_intent_routes_2026_11_25.json)。

## 控制及平台阶段

`/stair/status` 新增 `intent=move|turn|stop`。`turn=left|right|auto` 仍表示整项任务的转弯设置，不表示当前正在原地转向。

- `intent=turn` 时，规划库只保留零平移轨迹；控制器拒收仍含平移的旧 Path，定时输出也强制 `linear.x=0`。切换意图先清掉旧命令，停车、VIO 和路径过期保护优先。
- 小角度对齐使用实际剩余角度，不再一律发一个偏转 75° 的虚拟点。原地角速度下限仍为 0.25 rad/s；平移下限仍为 0.25 m/s。虚拟转向点只是角度提示，不是可行走的支撑点。
- 对齐转向使用 0.5 s 的角度评分，碰撞评分仍检查完整预测轨迹。平台行走预测到局部目标后停住，避免把继续越过目标后的端墙当作拒绝接近目标的理由。楼梯跟踪代价使用 XY 平面距离：支撑点与相机轨迹的高度差不再被当作未完成的路程，也不会在靠近目标时维持过大的角度权重；高度约束仍由支撑图和碰撞检查执行。
- 楼梯尚未走完、仍有梯段俯仰或尚未确认落地时，沿测得的梯段方向寻找前方支撑；没有支撑就停车，不能提前横向转入平台。
- 平台明确区分进入、横移、转回下一梯段；进入阶段不能被一次转向跳过。相机位置按配置外参换算为与规划器相同的控制中心，端墙限制进入深度，横移保留转向空间，移动前先对齐。横移开始后锁定该次平台的横移线，端墙离开短时视野也不能再改变横移位置。只有有足够横向跨度的高墙才能限制进入深度，薄栏杆/立柱不能充当端墙。

最终平台固定最后一段楼梯的到达参考，机身收尾晃动不能重置它。常规进入距离检查保留；窄平台的实测端墙会限制可继续进入的距离，并为机身和安全净空留出空间。默认至少进入 0.30 m（控制中心半径加两个栅格），仍要求水平姿态、足下已观测支撑及停稳，缺少支撑继续停车。独立世界断言继续核验终点位置和停车漂移。

## 下楼 target 与路径

下楼搜索排除高于估计脚底加 `max_step=0.22 m` 的地面候选。搜索从控制中心附近的单个最近支撑根开始，避免多根搜索从扶手另一侧凭空起步。

目标经避墙、偏移及踏面方向修正后，重新构造到同一个目标的连接路径；满足逐格高度和可达条件时优先使用直接连接。`/stair/path` 不再保留上一帧的陈旧显示。最后的朝前约束只请求原地转向，不再从全局可达区域另选一个与原路径无关的“前方空旷点”。下楼最终移动目标还会再次检查高度。

原记录下楼约 +47.629 s 的目标比相机高 0.225 m、比估计脚底高 0.525 m；旧逻辑最后一步将较低的原路径端点替换成了前方高点。该替换路径已删除。

## 上楼斜视与部分可见踏面

当前深度中的水平支持点按上升方向拟合，而不是要求楼梯与相机正前方基本一致。全视窗拟合失败时，尝试有重叠的局部视窗；仍要求点数、独立支撑格数、坡度、覆盖范围、高度变化、相机高度和内点比例相容。

只在实际观察到的邻近踏面范围内消除台阶墙候选。立面连接上下踏面时，上支撑同时受附近实测支撑和拟合高度约束；整根占据柱的上边缘超过支撑加 0.22 m、触顶截断、未知和缺少支撑的墙候选都保留。高横挡不能仅因旁边有更高台阶就被擦掉。

上楼增加保守的投影空闲证据：整个体素的图像投影范围均看到更远的有效深度时，才按原占据置信度规则融合为空闲。单帧不能清除已确认占据，当前命中优先；近处细杆、遮挡、无效深度和相机背后的墙保留。下楼与普通导航不启用这项上楼过滤。

`bottom=-0.2 m`、`top=+0.2 m`、`min_wall_span_m=0.3 m` 保持不变。

所有新发布的移动目标都检查了路径对应关系；下楼还检查目标高度。固定旧姿态的反事实回放中，转向和停车会明显增加，因为原运动没有执行新指令；这不能用来估算修改后的通行速度或成功率。零平移指 `/cmd_vel.linear.x=0`；真实机身漂移仍需新实测及执行器反馈验证。

早期出现井口越界或终点过早到达的候选均被原断言拒绝，未推送；最终使用原断言重新完成两方向验证。
