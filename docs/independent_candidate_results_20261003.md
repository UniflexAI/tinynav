# 候选独立评分与排列一致性验证（2026-10-03）

结论：独立评分保留了 L 转弯的方向建议，但没有给死胡同提供稳定、唯一的建议；三次排列的共识耗时也不能普遍满足 8 秒有效期。保留为离线诊断，没有接入在线 websim 控制。

## 实现

每次请求仅呈现一个已有候选，同时保留目标、最近运动、方向观测、planner 报告、历史尝试与空间上下文；明确说明其他候选在单独请求中评估，不能把缺少其他候选解释为唯一可用。候选 commands、测量值和历史记录保持原样。

独立评估两项：

1. 观测等级：blocked=0（存在已观测足迹阻挡）、partial_observation=1（无已观测阻挡但某阶段有未知）、observed_probe=2（所有阶段足迹没有阻挡或未知标签）、uncertain=无法定级。等级 2 只描述历史观测完整程度，不证明当前安全或能脱困。
2. 探测价值：investigate / unsuitable / uncertain。依据最近观测、运动、目标方向和过往尝试，判断是否有证据支持有限的局部探测；不推断未来 planner 成功或不存在于观测中的出口。

每个候选使用正常、反转、轮换三种选项顺序，候选提交顺序也相应改变。所有题意不变。每个原快照及左右镜像都测试。

一致性检查要求每个候选两项结果在三种排列中都一致、模型观测等级与本地数值核对一致、最高观测等级至少为 2 且只有一个候选，其探测价值还必须稳定为 investigate。最高观测等级并列时，不能用模型的探测价值标签强行打破并列。缺漏、格式错误、未知、数值核对错误或排列不一致都保留“不确定”。输出仅为离线 advice，未触发任何命令。

这里的本地数值核对直接读取已有 stage fractions，不是修改 planner，也不产生新观测。没有用选项权重相加或人为调节阈值来强制选择方向。

## 测试规模与输入检查

7 个已有快照，原场景及镜像共 14 个场景，92 个候选/场景组合，各测试三种排列，共 276 个请求、552 个独立问题提示词。

所有提示词通过当前每槽 4,096-token 容量检查，与 llama.cpp 的 tokenizer IDs 一致，每次响应 usage 与审计渲染数一致。提示词最大 1,769 tokens，没有改变模型、运行参数或有效期。完整输入、提示词、响应和时序均已保存。

这是对固定快照的重复评分，不能当成独立环境试验、闭环成功率或泛化准确率。

## 结果

| 指标 | 死胡同（4 原场景+4 镜像） | L 转弯（3 原场景+3 镜像） |
| --- | --- | --- |
| 观测等级符合本地数值核对 | 186/192 | 84/84 |
| 三种排列中观测等级稳定的候选/场景组合 | 58/64 | 28/28 |
| 三种排列中探测价值稳定的候选/场景组合 | 55/64 | 28/28 |
| 最终一致性检查 | 8/8 不确定 | 原场景 3/3 右转、镜像 3/3 左转 |
| 全部候选评完一种排列的耗时中位数 | 8.76 秒 | 6.74 秒 |
| 三种排列共识的耗时中位数 | 26.25 秒 | 20.22 秒 |
| 共识耗时超过既有 8 秒有效期 | 8/8 | 4/6 |

L 转弯中最少候选的两个场景共识耗时为 6.48/6.65 秒，其余四个约 20 秒。单个请求通常只需约 1.1 秒，但不能据此声称整个决策能在有效期内完成。

死胡同的 6 个场景因排列不一致而拒绝选择，另 2 个原场景因左右完整观测候选并列而拒绝选择。8 个场景中的“不确定”不是执行失败或到达结果。

总共 270/276 次观测等级符合本地数值核对。6 个错误均为把历史足迹已完整观测的候选判成部分未知；这次没有发现未知候选被提升为完整观测。不能将此解释为未来不会错误。

L 转弯仍只有单侧 pivot 可用，因此其方向选择与镜像对应，并不能充分证明模型能在双侧有竞争的候选中可靠判断脱困方向。对称死胡同中没有额外观测能证明唯一优越方向，检查并列会保留不确定，这属于本轮预先规定的保守行为。

## 结论与后续建议

独立评分没有消除所有排列敏感性。一致性检查确实挡下了不稳定或并列建议，但没有新增脱困效果证据；276 个请求没有执行动作，也没有新的到达率或碰撞率。

建议下一步把能直接计算的观测检查留给本地，只让模型评价少量候选的策略价值，降低调用量。同时用同一批快照比较模型的判断稳定性。若要解决左右同样可探测时如何决策，还需单独定义观测或探索策略，而不能把本轮“不确定”直接改成强制左转/右转。
