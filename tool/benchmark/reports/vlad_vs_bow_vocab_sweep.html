建图/补建索引阶段 CPU 占用（3 张图平均，%，单核=100%）

下图 GPU 全是 0，不是漏测：这批测试复用了之前已经算好并缓存的 DINOv2 patch token（patch_tokens.db），build_vlad_index.py 每次都会先检查 token 是否已存在，存在就跳过 DINOv2 推理，只重跑 k-means 训练+重算描述子——纯 CPU。真正需要 GPU 的"算 patch token"是一次性步骤，在这次词典扫描之前就做完了：GPU 利用率 ~9-32%、显存 ~450-480MB、1100-1160 帧耗时 ~30秒，且与词典大小无关。
这里的 CPU% 没有做线程限制，数字偏高：另一轮实验里（对 eval 阶段的检索脚本）把 OMP_NUM_THREADS/OPENBLAS_NUM_THREADS 锁定为 1 后，BoW 的 CPU mean 从 1167% 降到 819%（且跑得更快），VLAD 几乎不受影响（scipy cKDTree 走的是另一套并行机制）。这里的补建索引 CPU 没有重新用锁线程跑一遍验证，但大概率同样存在 BLAS 线程池超订阅的水分——尤其 BoW 那条曲线，真实需要的计算量应该比图上低。详见 vlad_vs_bow_final_report.html 里的线程池实验小节。
